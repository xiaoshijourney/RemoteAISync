# RemoteAISync 全链路启动指南

本文按当前仓库的启动方式说明如何运行完整链路：

```text
手机 / 浏览器客户端 → Ubuntu 公网中继（WSS）← Windows Agent 主机
```

也说明同一局域网直连和 Ubuntu 服务器直接作为 Agent 主机的用法。Windows BAT 是开发启动入口，主机服务由 Windows GUI 管理；Ubuntu 公网中继由 systemd 管理。请勿把本机开发中继和公网 Ubuntu 中继混为一谈。

## 1. 组件与端口

| 组件 | 启动方式 | 默认地址 / 端口 | 用途 |
| --- | --- | --- | --- |
| Windows 主机 GUI | `start_host.bat` | 本机桌面窗口 | 查看 Agent、控制主机服务、配置中继、配对手机 |
| Windows 主机服务 | 在主机 GUI 的主机模式中启动 | 本机 `8910` | 连接本机 Agent 并向客户端提供会话能力 |
| Web 客户端 | `start_client.bat` | `http://localhost:8911` | 在浏览器打开 RemoteAISync 客户端 |
| 本机开发中继（可选） | `start_relay.bat` | `8920` | 仅用于本机/可信网络调试，不是公网中继 |
| Ubuntu 公网中继 | `remotaisync-relay.service` | 公网 `443`，内部回环 `8920` | 通过 Caddy 提供 WSS 和中继转发 |
| Ubuntu 直连 Agent 主机（可选） | `remotaisync-host.service` | 公网 `443`，内部回环 `8910` | Ubuntu 服务器自身运行 Agent，手机经 WSS 直连 |

`0.0.0.0` 是服务监听所有网卡的地址，不是浏览器访问地址。电脑本机访问 Web 客户端用 `http://localhost:8911`；同 Wi-Fi 手机用电脑的 Wi-Fi IPv4 地址，例如 `http://192.168.1.20:8911`。

## 2. 首次部署 Ubuntu 公网中继

如果 Ubuntu 中继已经配置好并正常运行，可跳到“日常启动”。以下步骤只需在首次部署或更换服务器时执行。

### 2.1 DNS 与防火墙

1. 将 `relay.example.com` 的 DNS A 记录指向 Ubuntu 公网 IPv4 地址。
2. 在云防火墙和 Ubuntu 防火墙开放 TCP `80`、`443`；SSH `22` 按服务器管理需要保留。
3. 不要把 `8910`、`8920` 或 `/admin/*` 暴露到公网。
4. 确认服务器已安装 Caddy，并将 `deploy/ubuntu/Caddyfile` 安装为 `/etc/caddy/Caddyfile`。公网入口由 Caddy 终止 TLS，再转发到只监听 `127.0.0.1` 的 RemoteAISync 进程。

### 2.2 构建并安装中继

在 Linux x64 构建机或 Ubuntu 服务器上，从仓库根目录运行：

```bash
chmod +x deploy/ubuntu/build_linux.sh
deploy/ubuntu/build_linux.sh
```

构建产物是 `build/remotaisync`。Linux 可执行文件需在 Linux 上针对目标架构构建，不能用 Windows 构建产物替代。按仓库部署说明创建服务账号和目录，并将产物安装到 `/opt/remotaisync/remotaisync`。

首次安装时可执行以下命令（在项目根目录、构建完成后）：

```bash
sudo useradd --system --home /var/lib/remotaisync-relay --shell /usr/sbin/nologin remotaisync
sudo install -d -o root -g root -m 0755 /opt/remotaisync
sudo install -d -o remotaisync -g remotaisync -m 0750 /var/lib/remotaisync-relay
sudo install -d -o root -g remotaisync -m 0750 /etc/remotaisync-relay
sudo install -m 0755 build/remotaisync /opt/remotaisync/remotaisync
sudo install -m 0644 deploy/ubuntu/remotaisync-relay.service /etc/systemd/system/remotaisync-relay.service
```

若服务账号已存在，`useradd` 会提示该用户已存在，可继续检查目录和文件权限，不要重复创建不同账号运行同一个服务。

首次安装 Caddy 时，将 `deploy/ubuntu/Caddyfile` 中 RemoteAISync 对应的站点段合并进 `/etc/caddy/Caddyfile`；如果该文件已有其他站点，不要直接覆盖。域名应替换成你实际控制并已解析到此服务器的域名。

创建 `/etc/remotaisync-relay/relay.env`，可从 `deploy/ubuntu/relay.env.example` 复制。设置独立的随机管理密钥和主机注册码签名密钥（至少 32 个字符），文件权限应为 `0640`，不要把密钥放进文档、截图或公开日志：

```bash
sudo install -m 0640 -o root -g remotaisync deploy/ubuntu/relay.env.example /etc/remotaisync-relay/relay.env
sudoedit /etc/remotaisync-relay/relay.env
sudo chown root:remotaisync /etc/remotaisync-relay/relay.env
sudo chmod 0640 /etc/remotaisync-relay/relay.env
sudo systemctl daemon-reload
sudo systemctl enable --now remotaisync-relay
sudo systemctl status remotaisync-relay
```

安装并配置 Caddy 后重载、检查公网健康端点：

```bash
sudo systemctl reload caddy
curl --fail https://relay.example.com/health
```

健康检查可查看房间、主机和客户端连接数。公网客户端和 Windows 主机使用 `wss://relay.example.com`；不需要在手机上手动安装 CA 证书。

### 2.3 让 Windows 主机注册到中继

首次把一台主机加入中继时，在 Ubuntu 服务器本机签发一次性注册码。命令会输出注册码，只在安全渠道交给这台主机的操作者，不要粘贴到项目文档或聊天记录：

```bash
set -a
. /etc/remotaisync-relay/relay.env
set +a
/opt/remotaisync/remotaisync --mode relay --port "$REMOTEAI_RELAY_PORT" --issue-registration-code
```

在 Windows 主机 GUI 的**中继配置/连接设置**中填写中继地址 `wss://relay.example.com` 和该一次性注册码并完成注册。中继会为主机分配独立房间和房间凭据。手机不需要、也不应拿到中继管理密钥。注册码用过后不能重复使用。

## 3. 日常启动：Windows 主机 + Ubuntu 中继 + Web 客户端

### 第一步：检查 Ubuntu 中继

SSH 登录 Ubuntu，检查服务和健康端点：

```bash
sudo systemctl status remotaisync-relay
curl --fail https://relay.example.com/health
```

如服务未运行，启动并查看日志：

```bash
sudo systemctl start remotaisync-relay
sudo journalctl -u remotaisync-relay -n 100 --no-pager
```

### 第二步：启动 Windows 主机 GUI 和 Agent 服务

1. 在 RemoteAISync 项目根目录双击 `start_host.bat`。首次启动可能需要 Flutter 编译，等待桌面控制台打开。
2. GUI 进入**主机模式**，确认需要使用的 Agent 显示为可用。OpenCode 需要其本机服务可启动；Codex、Claude Code 需要本机可执行程序可被发现。
3. 若尚未注册中继，先按上面的注册码步骤在 GUI 中配置中继；如果已注册，确认中继状态在线。
4. 在 GUI 的**服务控制**中启动主机服务，等待状态变为“运行中”。仅打开 GUI 不代表主机服务已经启动。
5. 打开**连接信息 / 手机配对**，点击“生成手机配对二维码”。二维码包含主机配对邀请、可用的局域网地址和已配置的 WSS 路线。

主机服务默认使用本机 `8910`。不要同时用 GUI 和 `dart run host/bin/remotaisync_host.dart` 启动第二个主机实例，否则会出现端口 `8910` 已被占用。

### 第三步：启动 Web 客户端

在另一个终端或文件管理器双击 `start_client.bat`。该脚本在 `8911` 端口启动 Flutter Web 开发服务器。

- 本机浏览器：`http://localhost:8911`
- 同 Wi-Fi 手机浏览器：使用脚本显示的电脑局域网地址，例如 `http://192.168.1.20:8911`
- 不要访问 `http://0.0.0.0:8911`

如果 Windows 防火墙询问网络访问权限，允许 Dart/Flutter 在**专用网络**通信。只有在手机与电脑处于同一 Wi-Fi 时才需要开放 `8911` 的局域网访问。该 Flutter 开发服务器不是公网正式 Web 托管服务。

### 第四步：扫码配对并连接

1. 在 Web 客户端进入**连接**页，扫描 Windows 主机 GUI 上的二维码。浏览器使用摄像头扫码时需要 HTTPS 或 `localhost` 安全上下文；若手机浏览器不允许摄像头访问，可使用客户端手动输入作为备用，或在本机 `localhost` 打开客户端完成扫码。
2. 客户端会自动导入邀请，优先尝试可达的局域网路线；局域网不可达时使用二维码中的 WSS 中继路线。
3. 首次配对时，电脑 GUI 会显示待批准设备。在主机 GUI 的待批准设备列表中批准手机。
4. 客户端显示已连接后进入**会话**页，选择 Agent，再新建会话或打开历史会话。
5. 后续客户端保留设备凭据，可自动重连；若主机撤销了设备，需要重新生成邀请并配对。

如果手机在异地，手机访问的**客户端网页本身**也必须能从异地加载。当前 `start_client.bat` 只供本机开发和同一局域网预览；异地使用可部署 Flutter Web 静态构建产物到 HTTPS 网站，或使用 Android APK。客户端连接主机的数据链路仍走 WSS 中继。

## 4. 局域网双端直连

不使用中继时，确保手机和 Windows 电脑在同一 Wi-Fi：

1. 启动 Windows GUI 和主机服务。
2. 在 GUI 生成手机配对二维码。
3. 启动 Web 客户端并用手机打开电脑的局域网 IPv4 地址加 `:8911`。
4. 扫码并在电脑批准。

局域网直连不要求 Ubuntu 中继在线。Windows 防火墙需要允许主机服务端口 `8910` 和 Web 客户端端口 `8911` 在专用网络通信。不要为异地访问直接把 `8910` 映射到公网；公网主机请使用 TLS 反向代理/WSS，或使用中继。

## 5. Ubuntu 服务器直接运行 Agent 主机（可选）

如果 Codex、OpenCode 或 Claude Code 安装在 Ubuntu/VPS 本机，可运行 `remotaisync-host.service`，手机通过 `wss://host.<你的域名>/ws` 直接连接该主机，不需要中继。需要为主机域名配置 DNS、Caddy 路由和受信任 TLS 证书；公网只开放 `80/443`，主机服务继续监听回环地址 `127.0.0.1:8910`。详细安装、`host.env` 配置和主机注册码生成方式见 [Ubuntu 部署说明](../deploy/ubuntu/README.md)。

这与“Windows 主机通过 Ubuntu 中继异地连接”是两种不同拓扑：前者 Agent 运行在 Ubuntu；后者 Agent 运行在 Windows，Ubuntu 只转发连接。

## 6. 可选：Android APK

在项目根目录构建 release APK：

```powershell
flutter pub get
flutter build apk --release
```

APK 默认位于 `build\app\outputs\flutter-apk\app-release.apk`。连接手机并启用 USB 调试后，可用 `flutter install` 安装，或把 APK 传到手机手动安装。首次打开后扫描主机配对二维码并在主机 GUI 批准。Android APK 不依赖 `start_client.bat`。

## 7. 停止程序

- 停止 Windows 主机：在 GUI 点击停止主机服务；也可在项目目录运行 `stop_host.bat`。关闭 GUI 不一定等同于停止由 GUI 管理的服务。
- 停止 Web 客户端：在运行 `start_client.bat` 的窗口按 `q` 或 `Ctrl+C`；也可运行 `stop_client.bat`。
- 停止本机开发中继：在运行 `start_relay.bat` 的窗口按 `Ctrl+C`，或运行 `stop_relay.bat`。
- 停止 Ubuntu 公网中继：`sudo systemctl stop remotaisync-relay`。
- 重启 Ubuntu 公网中继：`sudo systemctl restart remotaisync-relay`。
- 跟踪 Ubuntu 中继日志：`sudo journalctl -u remotaisync-relay -f`。

Ubuntu 服务设置为开机启动，正常情况下不需要每次手动启动。

## 8. 常见问题

### 网页显示空白或无法打开

- 本机确认使用 `http://localhost:8911`，不是 `0.0.0.0`。
- 检查启动客户端的终端是否仍在运行，以及端口 `8911` 是否已被占用。
- 手机访问时确认使用电脑当前 Wi-Fi IPv4 地址，且电脑和手机在同一局域网；允许 Windows 防火墙的专用网络访问。
- `start_client.bat` 是 Flutter 开发预览，不是公网托管服务。

### 手机网页能打开，但连接主机失败

- 主机 GUI 中确认主机服务为“运行中”，所需 Agent 显示可用。
- 异地连接检查 Ubuntu relay 健康地址：`https://relay.example.com/health`，并确认主机 GUI 的中继连接在线。
- 同 Wi-Fi 直连确认 Windows 防火墙没有拦截 `8910`。
- 首次连接检查 GUI 的待批准设备列表；二维码过期后重新生成。
- 如果错误提示端口被占用，检查是否重复启动了主机服务。保留一个主机实例即可。

### 中继健康检查正常，但客户端数为 0

这表示当前没有客户端连接到中继，不代表中继故障。确认 Windows 主机隧道在线，手机已使用配对二维码，并且首次设备请求已在主机批准。

### 服务启动后 Agent 显示未安装/不可用

主机程序可以在 Agent 缺失时保持运行。检查 Agent 是否安装在运行主机服务的同一 Windows 用户环境中、可执行命令是否在该环境的 PATH 内；OpenCode 还需要本地 Server API 服务成功启动。

### 中继或主机重启后房间失效

不要删除 Ubuntu 的 `/var/lib/remotaisync-relay` 数据目录。中继房间凭据保存在该目录；同时妥善备份受保护的环境配置文件。丢失后主机需要重新注册并配对。

## 9. 安全要点

- 公网中继使用 `wss://`，主机直连公网也必须经 `wss://` 和受信任 TLS 证书。
- `ws://` 仅用于可信局域网、VPN 或本机开发，不用于公共互联网。
- 中继管理密钥只保存在 Ubuntu 中继端；一次性主机注册码只交给对应主机；手机仅保存自己的设备凭据。
- 不公开配对二维码、注册码、访问令牌、`relay.env` 或 `host.env` 内容。
- WSS 保护客户端/主机到 TLS 入口之间的传输；当前中继仍可读取应用层转发内容，尚未实现端到端加密。
